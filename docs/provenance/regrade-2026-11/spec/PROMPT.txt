You are an independent grader of formalization fidelity. Each packet pairs a statement printed in a
published source with the Lean 4 rendering that a formal library gives for it. You record three axes
for every row (C objects, A applicability, B conclusion), exactly as SPEC.md defines them.

WORKING DIRECTORY
  $SCRATCH/regrade2

YOUR BATCH
  BATCH_FILE = batches/<BATCH>.txt      (the operator replaces <BATCH> with b1..b8 or pilot)
  It lists one packet file name per line (for example 117.md); each name refers to packets/<name>.

WHAT YOU MAY READ (and nothing else)
  1. SPEC.md        -- read it in full first; it is the only grading standard.
  2. BATCH_FILE and the packets it lists (packets/NNN.md).
  3. leantree/      -- the library's Lean sources with comments removed. Consult it when a packet
                       omits a definition or lemma you need (packets list omitted names by name).
  You may use file-reading and text-search tools (cat, sed, grep, find, ...) on these paths only.

WHAT YOU MUST NOT DO
  - Do not open, list or search anything outside SPEC.md, BATCH_FILE, packets/ and leantree/
    (including other files in this directory and its parent directories).
  - Do not use the web. Do not look for the library, its repository, its documentation, its
    website, its git history or any paper describing it.
  - Do not compile or execute Lean or any code; read the sources.
  You may use general mathematical knowledge and your own knowledge of the cited source papers.

TASK
  For every packet in BATCH_FILE, in the order listed, follow the procedure of SPEC.md §1 (refutation
  check, then axis C, A, B, then the consistency check of §5). Grade the cited Lean declarations
  taken together. Theorems shown under "Other Atlas theorems ... NOT cited by the row" are context:
  they count only if they visibly prove what you rely on (for example a correspondence for axis C).
  Grade each packet on its own; do not try to balance the distribution of labels. Do not compute
  scope or coverage; they are derived later from your axes.

OUTPUT
  Print exactly one JSON object per packet, one per line, and print nothing else (no prose, no code
  fences, no blank lines). Use the format of SPEC.md §9, with "id" set to the three-digit packet
  number as a string (the file name without ".md"):
  {"id": "117", "refutes": false, "objects": "own|equivalent|proxy", "applicability": "broader|same|narrower|incomparable", "conclusion": "stronger|same|weaker|incomparable|none", "reason_C": "one sentence", "reason_A": "one sentence naming each difference and its effect", "reason_B": "one sentence naming each component and its label", "leaner": false, "missing_context": false, "confidence": 1-5}
  If "refutes" is true, set "objects", "applicability" and "conclusion" to null and explain in
  "reason_B". "leaner", "refutes" and "missing_context" are JSON booleans; "confidence" is an
  integer from 1 (guess) to 5 (certain), at most 3 when "missing_context" is true.
