## One-paragraph truth

v0.5 changes the Atlas's accounting and contribution model. The repository now
has one source-neutral results ledger: survey claims, claims from other sources,
and formalization artifacts are rows with different validated shapes. Absolute
workbench metrics replace survey-row fractions as the public headline. Sources
are classified as directories or statement-bearing works; only works can support
a statement-match grade. A generated mathematical-area index, a contained
conjecture intake path, and a `tasks.yaml` task board make the workbench usable by
new contributors without turning source completeness into a standing obligation.
The release also hardens the validators, generated-view ownership, declaration
provenance, reproduction-command checks, and concrete non-vacuity witnesses.
No theorem statement, statement-match grade, or reviewed bridge status changes in
this release.

## What changed since v0.4.0

| Area | v0.5 |
|---|---|
| Results ledger | `registry.yaml` is the single machine-readable results ledger; `BY-*` remains the closed survey block, `CLM-*` records claims from other sources, and `LAND-*` records formalizations standing on their own account |
| Public accounting | README and generated status pages report absolute declarations, claim results, artifact results, reviewed bridges, conjectures, and conservative statement-match counts; the survey remains available as a source-specific report |
| Source model | `source_catalog` distinguishes curated `directory` sources from statement-bearing `work` sources; only a work may support a relationship grade |
| Navigation | `docs/status/by-area.md`, compact agent indexes, one generated routing table, and source reports are derived from the ledgers rather than maintained separately |
| Conjecture intake | `conjectures.yaml` records compiling, non-theorem statements with `OPEN`, `RESOLVED`, or `WITHDRAWN` status; modules are isolated from the root import and explicit build closure |
| Contributor workflow | `tasks.yaml` is the maintained task board; `docs/guide/contributor-tasks.md` is generated, with status/badge and cross-reference validation |
| Discovery evidence | The six-corpus search is a source-scoped `baseline-catalogue` profile; claims of absence use a claim-scoped `novelty-check` with corpus, revision, date, and scope limits |
| Validation | Artifact rows, declaration shapes, source roles, provenance, root-import flags, generated views, reproduction entry points, and gate witnesses are checked; malformed ledgers are covered by 60 regression cases |
| Lean trust | Concrete witnesses cover the published nontriviality, Rashomon, regret, and anonymous-algorithm gates; all explicit targets remain in the strict-trust build closure |

## Critical non-claims

- **No new mathematics is claimed by the process refactor.** Existing theorem
  statements and their conservative relationship grades are unchanged.
- **A conjecture is not a theorem.** Its compiling proposition is isolated from
  the public root and does not enter theorem or coverage counts.
- **A candidate lead is not a formalization.** Reproduction and statement-level
  classification are still required before coverage changes.
- **A zero search result is not a proof of absence.** Search evidence is pinned,
  scoped, and explicit about what it did not cover.
- **Generated documentation is not an edit surface.** Contributors edit the
  ledger, task board, or search generator inputs, then regenerate and gate.
- **Machine checking is not system validation.** AI-system interpretations remain
  separate reviewed bridges and no bridge graduates in v0.5.
